# NoteLume 剪藏（浏览器扩展）

把网页正文剪藏到本机 NoteLume 知识库：按模板落盘成标准 GFM md，图片可选本地化，文末自动追加「\#\# 相关笔记」关联库内已有文档。

MV3，无构建、无 npm 依赖。`vendor/` 下是三个原样放入的库：

- `defuddle.js` —— defuddle 0.19.5（MIT，npm 包 `dist` 的 UMD 浏览器包，全局名 `Defuddle`，无外部依赖）
- `Readability.js` —— @mozilla/readability（Apache-2.0）
- `turndown.js` —— turndown 7.2.0（MIT）

## 安装

Edge / Chrome：开 `edge://extensions`（或 `chrome://extensions`）→ 打开左下角「开发人员模式」→「加载已解包的扩展/加载未打包的扩展程序」→ 选本目录。

## 配置

右键扩展图标 →「扩展选项」（或 `edge://extensions` 里点详情 → 扩展选项）：

- 服务器地址：NoteLume 剪藏设置里显示的地址，默认 `http://127.0.0.1:3210`。端口被占用顺延过就以 NoteLume 里显示的实际端口为准。填这一项就够了，没有令牌要配
- 默认目标目录 / 默认模板：可选，填了就对每次剪藏生效，覆盖 NoteLume 设置里的对应值

「测试连接」会请求 `GET /health`，能看出服务在不在、端口对不对、NoteLume 有没有开着知识库。

每次剪藏前扩展也会读一次 `/health`，拿 NoteLume 剪藏设置里的两个开关：图片本地化（`clip.localizeImages`，默认关）与整页兜底（`clip.fullPageFallback`，默认关）。NoteLume 没启动时按默认值继续，随后的 POST 会以「连不上」报错。

NoteLume 侧：工具条「更多 → 网页剪藏设置」里启用服务、选模板与目标目录、目标目录、图片本地化与整页兜底两个开关。

## 使用

- 点工具栏图标：页面上有选区就剪选区，没有选区才剪整页
- 右键菜单「剪藏选中内容到 NoteLume」：只剪选中的片段（先在页面上选中文字），走内置 highlight 模板（来源行进引用块）。选区在输入框里、或页面嵌在 iframe 里时，浏览器给的选中文本会兜底（纯文本，无图片与链接）
- 右键菜单「截取选区图片剪藏到 NoteLume」：把选中的那块画面截下来存成图（快捷键 `Alt+Shift+S` 同一条路）。选区是一张图、一个图表、一段代码截图都行，同时选中的文字会跟着图一起存
- 右键菜单「框选区域截图剪藏到 NoteLume」：在页面上拖一个矩形，截下那一块（快捷键 `Alt+Shift+D` 同一条路）。浏览器的选区只能圈文字，圈不住图表与插图，框选补的就是这一段——页面上会出现一层暗色遮罩，拖出选框，松开即截；`Esc` 取消
- 右键菜单「剪藏整页到 NoteLume」：强制剪整页，有选区也剪整页

提取按优先级降级：Defuddle → Readability + Turndown →（设置开了才有）整页 HTML。Defuddle 内部提取失败时不抛错，而是把整个 body 当正文返回（没有语义主标的 div 汤页也会退到 body 入口，把导航侧栏留下来），`extract.js` 按内容长度、字数与元数据识别这种假成功，同样降级 Readability。正文尾部博客平台挂的签名块（本文作者 / 本文链接 / 版权声明 / posted @ 阅读(…) 评论(…) 收藏 举报 / © …）不是正文，从结尾往前整段切掉，切口落在内容前 60% 之内才动手，正文里提到这些词不受影响。选区剪藏不走提取器，划了什么存什么。图片本地化默认关：正文保留原链接；在 NoteLume 设置里打开后，扩展才把图 fetch 成 data URI 随载荷传来，落 `<目标目录>/assets/`。

截图剪藏走另一条路，不跑提取器也不取远程图：页面侧量出选区矩形，扩展拍下当前可视视口裁出那一块，落成 `<目标目录>/assets/clip-<时间戳>.png`，正文里是一张本地图片。截图恒定落盘，与「图片本地化」开关无关。截图只能拍到当前视口里的画面——选区有一截在视口外时先把它滚进视口再截；选区比视口还大时只能截到看得见的那部分，通知里会说明。

框选截图与上面同一条落盘链路，只是矩形的来路不同：页面上拖出来的框。拖动时页面盖一层暗色遮罩、跟着鼠标画选框，松开后遮罩与选框立即撤掉（截图拍的是当前画面，遮罩留着就被拍进去了），再拍那一块。框出来的图与选区截图一样落 `<目标目录>/assets/`，正文是一张本地图片，不带选中的文字（框选圈的是画面，不是文字）。

处理中图标徽标转圈，成功 / 失败都有系统通知，通知里带落盘路径、图片数与关联篇数（图片段只在本地化开启且有图落盘时出现）。

右键菜单在安装 / 更新 / 浏览器启动时重建：菜单注册在浏览器侧，浏览器重启会清掉它，而负责重建的 service worker 在那时不触发安装事件——只在安装时建一次，重启后就只剩工具栏图标。

## 失败提示对照

| 提示 | 原因 |
| --- | --- |
| 连不上 NoteLume | 应用没启动，或剪藏服务没启用，或地址端口不对 |
| 请先打开一个知识库 | NoteLume 开着但没开库 |
| 内容超过大小上限 | 单次载荷超 8MB、正文超 2MB、单图超 5MB |
| 页面提取失败 | Defuddle 与 Readability 都没有结果，且整页兜底关着（默认） |
| 没有选中内容 | 选了「剪藏选中内容」但页面上没有选区；截图剪藏同理，且跨域 iframe 里的选区读不到 |
| 没有选到区域 | 框选时拖动的面积太小（当误点处理了），或按了 `Esc`——这两种是取消，通知里写「已取消」，不算失败 |
| 截取当前标签页失败 | 浏览器拒绝截取这个标签页（部分受管控页面会拒绝） |
| 请求超时 | 15 秒没等来响应 |

## 安全边界

服务只绑 `127.0.0.1`，不带令牌：请求带 `Origin` 时必须是扩展来源（`chrome-extension://` / `moz-extension://`），网页的 fetch 与表单提交到不了；`Host` 必须是回环名，DNS rebinding 到不了。本机其他进程写得了库里的文件，HTTP 服务没给它们新能力，为此设令牌只会把复制粘贴的成本转嫁给正常用户。
