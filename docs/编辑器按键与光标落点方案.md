# 编辑器按键与光标落点方案

覆盖四类常规按键毛病：退格删掉上一整块、表格回车出不去、代码块与列表回车落点不对、标题回车凭空多一个标题。事务级实测在 jsdom 里加载真实 schema 与真实命令链（不发键盘事件），键位与光标落点另在浏览器里逐条按过，边界见第 7 节。

## 1. 现状与根因

按键链路的三层结构：`buildEditorKeymap` 的仓库键位（`src/editor-view.js:119`）优先，其次 `keymap(baseKeymap)`（`src/editor-view.js:252` 装配）。仓库键位返回 false 时，PM 继续问 baseKeymap，所以「重绑一个键」等于「给这个键多插一层前置命令」，前置层返回 false 就退回原生行为。baseKeymap 只有 `Enter`（`prosemirror-commands/dist/index.js:815` 的 chainCommands）与 `Mod-Enter: exitCode`（同文件 816），没有 `Shift-Enter` 键——那一档只有仓库这一层，前置链返回 false 就是彻底无事发生。

下表是改前状态。改动的代码位置用符号名指（行号已随本轮改动漂移），依赖包内的行号仍可直接对。

| 症状 | 触发条件 | 现状 | 根因位置 |
| --- | --- | --- | --- |
| 空行按退格，上一整块消失 | 光标在任一块的开头，按一次选中、再按一次删除 | 段落 / 标题 / 列表 / 表格 / 代码块 / 脚注区六类实测全中 | `buildEditorKeymap` 的 `Backspace` 位是裸 `selectNodeBackward` |
| 表格里回车无反应，光标不动 | 光标在单元格内 | Enter、Mod-Enter 均无事务；Shift-Enter 只塞硬换行 | 单元格 `cellContent: 'inline*'`（`src/editor-schema.js:37`）+ prosemirror-tables 的 `isolating` |
| 表格在文末时，表下面写不了字 | 文档末块是 table | 文档里没有表后的落点，重开文件也一样 | 无 gapcursor、无 `appendTransaction` |
| 代码块回车出不去 | 光标在代码块末行 | 永远只在块内插 `\n` | baseKeymap 的 `newlineInCode` 先命中（`prosemirror-commands/dist/index.js:815`） |
| 列表末项回车不出新项 | 光标在最后一个列表项末尾 | 在同一项里加第二个段落，项数不变 | `list_item` 是 `content: 'block+'`（`src/editor-schema.js:67`），`splitBlock` 认为块内分裂合法 |
| 脚注项内回车无反应 | 光标在脚注正文末尾 | 无事务 | `footnote_item` 是 `content: 'paragraph'`（`src/editor-schema.js:353`），只容一个段落 |
| 标题中间回车凭空多一个标题 | 光标在 heading 内 | 拆成两个 heading，md 里多出一行 `#` | `splitBlock` 按 heading 自身 `content: 'text*'` 分裂，兄弟类型仍是 heading |
| 标题里 Shift-Enter 写坏原文 | 光标在 heading 内 | 序列化出 `# 标` + 空行 + `\` + `题`，反解后标题少半截、多一个乱段 | 硬换行在标题里没有 markdown 形态，而改前的 `nlHardBreak` 不看块类型直接插 |

退格那条是唯一会造成内容消失的，先修这条。原生链的行为是合并两行、光标回到上一块末尾、一个字不丢——正是需要的「回车之后删掉回到原来的位置」。

## 2. 退格：接回 joinBackward，同时保住原子块的按一下选中

裸 `selectNodeBackward` 里的 `findCutBefore` 会沿祖先爬到顶层，只要左侧有兄弟块就返回该兄弟节点；而仓库没有任何节点声明 `selectable: false`，于是段落也被当成「可选中的整块」。直接改回原生链会带一个新问题：`joinTextblocksAround` 对代码块同样成立，实测会把光标所在段落的正文并进上方代码块的最后一行（`let a = 1` 与「下面还有正文。」拼成一行）。

按上一块类型分派的规则：

| 上一块 | 第 1 次退格 | 第 2 次退格 |
| --- | --- | --- |
| paragraph / heading / blockquote / callout / 列表 / footnote_section | 与当前文本块合并，光标落在上一块末尾 | 继续在当前块内向左删字符 |
| code_block（含 mermaid 围栏） | 选中整块 | 删整块 |
| table（isolating，合并必返回 false） | 选中整表 | 删整表 |
| math_block / math_inline / image / footnote_ref / hr（atom，无子节点） | 选中整块 | 删整块 |

实现：`src/block-commands.js` 新增 `nlBackspace`，绑到 `buildEditorKeymap` 的 `Backspace`，替换现有的裸 `selectNodeBackward`。

```
const backspaceChain = chainCommands(deleteSelection, joinBackward, selectNodeBackward)
nlBackspace(state, dispatch, view):
  if $cursor 存在（选区为空且是 TextSelection）
     且 光标在当前文本块开头（用 view.endOfTextblock('backward') 判，缺 view 时退化为 parentOffset === 0）
     且 沿祖先找到的左侧兄弟（跳过 isolating 层）是代码块或原子块
  then return selectNodeBackward(state, dispatch, view)
  else return backspaceChain(state, dispatch, view)
```

沿祖先找左侧兄弟的这七行等价于 `findCutBefore`（该函数未导出），必须照抄该函数的两条终止条件：`$pos.parent.type.spec.isolating` 直接放弃、途中撞到 isolating 节点即停。

Backspace 不进命令注册表：`normalizeBinding` 只接受单字符基础键、F1–F12 与带修饰的 Tab（`src/keymap.js:26`），`'Backspace'` 非法，重绑不了；沿用现有的「固定结构键」一档（注释在 `src/editor-view.js:37-40`），`docs/CLAUDE.MD`「快捷键规范」同步按键链路说明与固定结构键表。

单测 `src/tests/backspace.test.mjs`（15 例，纯 state 层无需 DOM；下表之外另有 mermaid 围栏同代码块一档、分割线走选中、文档首块行首不接管、引用内末段并入上一段、跨引用容器合并只去标记）：

| 用例 | 前置 | 期望 |
| --- | --- | --- |
| 段落行首退格 | `第一段。\n\n第二段。`，光标在「第二」前 | 文档变一个段落，正文「第一段。第二段。」，不产生 NodeSelection |
| 标题行首退格 | `# 标题\n\n正文。` | 合并，无选中 |
| 代码块后段落行首退格 | 代码块 + 段落 | NodeSelection 覆盖 code_block；第二次删整块，段落正文保留 |
| 表格后段落行首退格 | 表格 + 段落 | NodeSelection 覆盖 table（isolating 挡住合并） |
| 原子块后段落行首退格 | math_block + 段落 | NodeSelection 覆盖 math_block |
| 行中选区退格 | 段落中间，光标后有文字 | 退格返回 false，走 base 链按字符删 |
| 有选区退格 | 选中若干字 | deleteSelection 先命中，删选区不合并块 |
| 表格内部退格 | 单元格中间 | 不越出 isolating 边界（负例） |

## 3. 表格：格内走格，末格出表

单元格是 `inline*` + isolating，原生链的四档 `splitBlock`、`newlineInCode`、`liftEmptyBlock`、`exitCode` 在格中和格末实测全 false（`src/tests/table-enter.test.mjs` 末条负例），所以 Enter 必须给专用命令：放行了等于交回一条什么都做不了的链，光标照旧原地不动。

`nlCellEnter`（`src/table-editing.js:220`）：

1. 不在表内 → 返回 false，交回回车链。
2. 在表内 → `goToNextCell(1)`（prosemirror-tables 的同一命令也用于 Tab，`src/table-editing.js:183`），跨行、跨合并格的顺序由它内部的网格计算给出；合并格算一格，实测 colspan=2 的表走格顺序 a → b → 合并格 → 出表。
3. `goToNextCell` 在末格返回 false → 走 `exitTableBelow`（`src/table-editing.js:200`）：表后有兄弟块时 `TextSelection.near(表后位置, 1)` 进该块第一个文本块，只搬光标不改文档；表是文档末块时才 `tr.insert` 一个空段落并把光标放进去，再 `scrollIntoView`。

表内一律接管、不看选区。`goToNextCell` 落格后在模型里留的是「所在格边界处长度 1」的选区（实测 anchor 6 / head 7，`$from.parent` 就是那个单元格文本块），按「有选区就让行」判定会把连按的第二下挡断；浏览器还会把它夹进文本，实测成目标格首字被选中——走格后打字即替换、按退格即清掉该格首字。这一形状与 Tab 走格完全一致（同一条上游命令），不是本轮新引入的。

绑定点：`buildEditorKeymap` 的 map 里有 `'Enter': nlEnter`（`src/editor-view.js:122`），`nlEnter` 是 `chainCommands(nlCellEnter, splitListItem, splitHeadingDown, 脚注档, newlineInCode, createParagraphNear, liftEmptyBlock, splitBlock)`。仓库原先不绑 Enter，加入后其余分支全部保留原语义，只是给「在表内」这一种情况加一层前置。

格内 Shift-Enter 改为上一格（`nlCellBack` = `goToNextCell(-1)`，`src/table-editing.js:227`），取消原来的插 hard_break：实测该行为会把表格写坏——单元格里的硬换行序列化成 `| c\` 换行 `下 |`，反解后行数 2 变 3、格数 4 变 6，反斜杠落成正文。GFM 表格行内本就不可表示换行，Typora 也不允许格内换行。Mod-Enter 在格内继续无效：`exitCode` 实测 false（见上），与「末格 Enter 已出表」不重复。

就地入口：表格右键菜单在「下方插入行」之后一项「表后另起一段」（`src/table-editing.js:318`、词条 `table.afterPara`），调用同一个 `exitTableBelow`；命令面板与 mac 原生「段落」菜单不加项，避免同一功能三处入口。

末格出表插的空段落是显式按键产生的事务，判脏与自动保存按正常链路走（`src/editor-view.js:289-301` 对任何 `tr.docChanged` 置脏）。但文档尾部的空段落序列化时会被吃掉（实测表格 + 空段落写出的仍是纯表格 md，见第 4 节），所以它只是当次会话的落点，不落盘；接着打字才有正文，那才会存下来。

单测 `src/tests/table-enter.test.mjs`（13 例）：走格顺序（含表头行、末行走格、跨 colspan）、末格出表两个分支（表后有段落 / 表是末块）、出表事务带 `scrollIntoView` 且不复制表格、非表格区域不接管与格内原生四档全 false（负例）、格内选中若干字仍走格、格内 Shift-Enter 回上一格且不产生 hard_break、出表后立刻退格不误删表（边界）。

## 4. 块后落点：gapcursor

表格、代码块、公式块在文档末尾时没有落点，鼠标点这些块下方的空白只会把光标送进最后一块里。解法两条，只能选一条：

- 装 `prosemirror-gapcursor` 1.4.1（新增一条 npm 依赖）。插件把块四周的间隙做成可点、可打字的光标位，落点只是一个选区，不改文档因此不判脏。
- `appendTransaction` 在末块不是段落时自动补空段落。代价不可接受：`dispatchTransaction` 对所有 `tr.docChanged` 一律置脏（`src/editor-view.js:293`），装载后 2 秒的自动保存会静默改写文件。

取第一条。落点判定全在 `GapCursor.valid`，两条：邻块要 `needsGap`（源码 `type.isAtom || spec.isolating || spec.createGapCursor`），且该位置的父块内容匹配能给出文本块默认类型，位置再被 `allowGapCursor` 覆盖。据此本轮的结果是：

| 文末块 | 给落点 | 依据 |
| --- | --- | --- |
| table | 是 | isolating |
| code_block（含 mermaid 围栏） | 是 | 三条都不占，靠 `src/editor-schema.js:234` 新加的 `createGapCursor: true` |
| math_block / hr | 是 | isAtom |
| 引用 / 提示块 / 列表 / 脚注区 | 否 | 容器块本身三条都不占（实测 false），范围内不做 |
| 普通段落 | 否 | 段末本来就能打字 |

表内必须关掉：间隙光标的判定看「所在父块」，行首/行尾位置的父块是 `table_row`，其 contentMatch 默认类型是 `table_cell`（实测 dir=-1 得 pos=10、父=table_row），落点停在那里再敲一次键就往行里插一个格。故 `table` 与 `table_row` 都加 `allowGapCursor: false`（`src/editor-schema.js:102`），表前后的落点父块是 doc，不受这条影响；从末格越界的方向键因此会一路上溯到文档层（复刻 `findGapCursorFrom` 实测得 `doc.content.size`）。

打字与存盘两条：光标位落在间隙时按键，PM 按父块（即 doc）的内容匹配自动补出段落再输入，间隙选中态本身无段落可承载；文档尾部空段落被序列化吃掉，所以落点活在编辑器会话里而不落盘。空段落有文字后就是普通段落，正常存盘。

装配：`gapCursor()` 放在主插件数组末尾、`...tablePlugins()` 之后（`src/editor-view.js:277`），让列宽拖拽先取得鼠标事件；1.4.1 的 `gapCursor()` 不接受参数。`src/style.css` 补两处：`.editor .ProseMirror` 加 `position: relative`（`:1799`，间隙元素按它绝对定位），以及 `.ProseMirror-gapcursor` 的伪元素样式（`:1801-1823`），颜色取现有 `--text-editor`，不引入新令牌；编辑器 `overflow-x: auto` 且换行可关，而 `valid` 只看块之间的位置，横向滚动与间隙不冲突。

与鼠标交互的关系已在浏览器核过：点表格下方空白取得间隙、打字成段、图片无损拖拽缩放与列宽拖拽不被抢事件；真键盘的方向键取位只做了结构层复刻，边界见第 7 节。依赖安装因此排在最后一步，出问题单独回退，不影响前三步。

## 5. 代码块、标题、列表、脚注的回车

代码块：Enter 只在块内换行是对的，缺的是出口与可见性。`exitCode` 已由 baseKeymap 绑在 Mod-Enter（`prosemirror-commands/dist/index.js:816`），仓库注册表加了 `{ id: 'editor.exitBlock', titleKey: 'cmd.editor.exitBlock', defaultKey: null }`（`src/editor-view.js:68`，命令位 `PM_COMMANDS['editor.exitBlock'] = exitCode` 在 `src/editor-view.js:113`），词条三语言各一条（`src/locales/zh-CN.js:85`、`zh-Hant.js:85`、`en-US.js:85`）。默认键留空是绑定串法限制：`normalizeBinding` 只接受单字符基础键、F1–F12 与带修饰的 Tab，`'Mod-Enter'` 判非法（`src/tests/keymap.test.mjs:31` 钉住这条），所以 Mod-Enter 的实际响应继续由 baseKeymap 提供，注册表项只负责让命令在面板与快捷键设置页可见、可搜。仓库 map 里不重复绑 `'Mod-Enter'`，重复一层只是死代码。

Shift-Enter：原链把 `exitCode` 放链首，所以代码块里 Shift-Enter 的实际动作是离开代码块，容器块（引用 / 提示块 / 列表项）末尾按它也整块跳出——与「硬换行」字面相反。现链 `nlHardBreak`（`src/block-commands.js`）分四档：表格里=上一格；当前文本块 `spec.code`= `newlineInCode`（块内换行，与 Enter 同果）；标题=返回 false，而 baseKeymap 没有 `Shift-Enter` 这一档，于是彻底无事发生；其余=插 `hard_break`。标题那一档必须留：硬换行在标题里没有 markdown 形态，实测序列化出 `# 标` + 空行 + `\` + `题一二`，反解后标题少半截、多一个乱段，改前同样插入，属既有的损坏路径。mermaid 摘图随之只剩 Esc、Mod-Enter 与「点击别处」（`src/mermaid-preview.js:8` 注释同批改）。

标题：Enter 走 `splitHeadingDown`（`src/block-commands.js`）。原生 `splitBlock` 会把 heading 拆成两个 heading（实测 `# 标题一二` 中间回车得 `['heading','heading']`），markdown 里凭空多一个标题。改法两条分支：光标不在行首→光标后的文字降到标题下方新起的段落，结果 `['heading','paragraph']`、md `# 标题\n\n一二`；光标在行首→没有后半截可搬，改为在标题上方插空段落并把光标放进去，标题本体不动。有选区不接管，交回原生分块（实测删掉选区并得到 `['heading','paragraph']`，不产生第二个标题）。

列表：Enter 链用 `splitListItem(N.list_item)`（`prosemirror-schema-list`，仓库此前只用过 `wrapInList`）——「当前项内新起一项」是它的语义，嵌套与任务项的深度计算自带。空项返回 false，交回现有 `liftEmptyBlock` 退出列表变正文（与 Typora 一致，事务实测正确）。多段落项（`list_item` 是 `content: 'block+'`）在最后一段落末尾时同样新起一项。

脚注项：`content: 'paragraph'`（`src/editor-schema.js:353`）只容一个段落，`splitBlock` 恒 false，Enter 原本无事发生。现链在脚注项内落 `hard_break`（`[^1]: 正文\` + 换行），三种落点往返实测全等——段中、段末、换行后接着打字，反解后文档与原树一致；多个脚注项各带一个换行也全等。末位只换行、后面不打字时该节点被序列化吃掉，与尾部空段落同性质：不损坏、不留孤立定义（不出现 `[^]:`）。Shift-Enter 与 Enter 同形。要「脚注内分段落」得先把 markdown-it-footnote 的续行往返修对（放开 `'paragraph block*'` 也在此后），另立一项。

## 7. 验证与边界

实测记录：

- 全量 36 个测试文件通过，`npm run build` 通过。新增四个文件合计 57 例，其中负例与边界 21 例（格内原生四档全 false、非表格区不接管、容器块与段落收尾不给落点、行首标题、空末项、末位换行被吃掉、间隙选区不改文档、出表后立刻退格、文档首块行首、引用内多段）。
