# 三端窗口与菜单栏入口方案

面向 NoteLume 的三平台落地：Windows / Linux 自定义标题栏、macOS 主窗口自定义标题条、macOS 菜单栏状态图标（NSStatusItem + NSMenu）、以及 Swift / Rust 通信。所有代码对准当前仓库的真实文件，不是模板。

先厘清两个已经存在、容易混淆的东西：

- `tauri-bridge.js` 里的 `set_mac_menu` / `lib.rs` 的 `install_app_menu`，建的是**屏幕顶部的 App 主菜单**（文件 / 编辑那一排），macOS 独有，靠 `menu.set_as_app_menu()`。它和本文要做的**菜单栏状态图标**是两套东西，不要混。
- 当前 `tauri.conf.json` 只有一个窗口配置，`titleBarStyle: "Overlay"`，没有 `label`（默认就是 `"main"`），也没有 `decorations` / `hiddenTitle`。Windows / Linux 下 `titleBarStyle` 被忽略，所以现在这两端看到的是系统原生标题栏。

## 跨平台窗口策略（先说清，避免踩坑）

macOS 的 `titleBarStyle: "Overlay"` 和 `decorations: false` 是冲突的：`decorations: false` 在 macOS 上会把整个标题条连同红黄绿按钮一起干掉。而 `tauri.conf.json` 是单一配置、三端共用，没法给 `decorations` 按平台分别设值。

所以采用**配置管 macOS、运行时管 Win/Linux**：

- `tauri.conf.json` 保持 `decorations` 默认（true），设 `titleBarStyle: "Overlay"` + `hiddenTitle: true`，这只在 macOS 生效，红黄绿按钮保留、标题文字隐藏。
- 在 `run()` 的 `.setup()` 里，非 macOS 平台调用 `window.set_decorations(false)`，把原生标题栏去掉，改由前端 `.titlebar` 顶上。

这样同一份配置：macOS 走 Overlay，Windows / Linux 走运行时去边框 + 自定义标题栏。

## 1. 改现有文件

### 1.1 `src-tauri/tauri.conf.json`

把 `app.windows[0]` 改成下面这样（保留原有宽高 / 最小尺寸，只补窗口相关字段）：

```json
"windows": [
  {
    "label": "main",
    "title": "NoteLume — Markdown 知识库编辑器",
    "width": 1240,
    "height": 820,
    "minWidth": 900,
    "minHeight": 600,
    "titleBarStyle": "Overlay",
    "hiddenTitle": true
  }
]
```

字段说明：

- `label: "main"`：显式写出来，`get_webview_window("main")` / 前端 `getCurrentWindow()` 都按它走。不写也是 `main`，写清楚省得以后加窗口时踩。
- `titleBarStyle: "Overlay"`：macOS 专用。标题条区域透明，webview 内容延伸到顶部，红黄绿按钮浮在内容左上角。这是做自定义标题条的正解。
- `hiddenTitle: true`：macOS 专用，配合 Overlay 用，把居中的标题文字藏掉，只留按钮。
- 不建议给主窗口设 `transparent: true`：整窗透明会丢阴影、还可能点击穿透，做标题条用 Overlay 就够，不用整窗透明。
- `visible`：默认 true。NoteLume 是有完整编辑器的主窗口应用，启动即显示，不要设 false。只有纯菜单栏工具才 `visible: false` 起步。

`decorations` 这里**不写**，交给下面的运行时逻辑按平台处理。

### 1.2 `src-tauri/src/lib.rs` —— `run()` 加 `.setup()`

当前 `run()`（`lib.rs:2978` 起）没有 `.setup()`。在 `.on_menu_event(...)` 之前插入一个 `.setup()`，做两件事：非 macOS 去边框；建菜单栏图标（见第 5 节，先只放去边框）。

```rust
.setup(|app| {
    // 非 macOS：去掉原生标题栏，改由前端 .titlebar 顶替。
    // macOS 保留 Overlay（红黄绿按钮 + 透明标题条），不碰。
    #[cfg(not(target_os = "macos"))]
    {
        if let Some(win) = app.get_webview_window("main") {
            win.set_decorations(false).map_err(|e| e.to_string())?;
        }
    }
    Ok(())
})
```

`set_decorations` 返回 `tauri::Result`，`.setup()` 要返回 `Result<(), Box<dyn Error>>`，`map_err(|e| e.to_string())?` 能把错误转成 `String` 再 `?`（`String: Into<Box<dyn Error>>` 成立）。

### 1.3 `src-tauri/capabilities/default.json`

现在只有 `core:default` / `dialog:default` / `core:webview:allow-print` / `core:window:allow-destroy` / `core:window:allow-set-title`。前端要控窗口，得显式补窗口命令权限（Tauri v2 白名单制，不给就用不了）：

```json
{
  "$schema": "../gen/schemas/desktop-schema.json",
  "identifier": "default",
  "description": "主窗口默认权限：核心 API + 文件夹选择对话框 + 关闭窗口前可销毁（未保存询问）+ 设置窗口标题 + 打印（mac 的 window.print 走 IPC）+ 自定义标题栏窗口控制 + 菜单栏事件监听",
  "windows": ["main"],
  "permissions": [
    "core:default",
    "dialog:default",
    "core:webview:allow-print",
    "core:window:allow-destroy",
    "core:window:allow-set-title",
    "core:window:allow-minimize",
    "core:window:allow-unminimize",
    "core:window:allow-maximize",
    "core:window:allow-unmaximize",
    "core:window:allow-toggle-maximize",
    "core:window:allow-close",
    "core:window:allow-show",
    "core:window:allow-hide",
    "core:window:allow-set-focus",
    "core:window:allow-is-maximized",
    "core:window:allow-start-dragging"
  ]
}
```

逐条对应用途：`minimize` / `toggle-maximize` / `close` 是三个标题栏按钮；`is-maximized` 用来判断最大化按钮显示方框还是双框；`show` / `hide` / `set-focus` 供菜单栏唤醒隐藏的主窗口；`start-dragging` 是程序化拖窗（`data-tauri-drag-region` 走 CSS 那条路，这个按钮留作兜底）。

如果用第 5 节方案 B（Swift 插件），事件是 Rust → JS 的 `emit`，`core:default` 已含 `core:event:default`，不用额外加。如果用方案 A 且希望 JS 也能直接操作托盘，再补 `core:tray:default`；本例托盘事件全在 Rust 侧处理，JS 不碰，不加。

### 1.4 `src-tauri/Info.macOS.plist`

保持普通应用形态（有 Dock 图标、能 Cmd-Tab），**不设** `LSUIElement`。要不要设 `LSUIElement` 见第 7 节。

除了本地化键，这份还声明 `CFBundleDocumentTypes` 三组：md / markdown 与 canvas 两类是 `Editor` + `LSHandlerRank: Default`，第三组 `public.folder` 是 `Viewer` + `LSHandlerRank: None`，让 Finder 与 Dock 愿意把文件夹递进来（拖到 Dock 图标、右键「打开方式」选到本应用）。两点要注意：

* `bundle.macOS.infoPlist` 是整份 plist 的浅合并，`CFBundleDocumentTypes` 属于**整组覆盖**而非追加——写在 `Info.macOS.plist` 里就以此处为准，构建产物里这个键只剩这三组（已用打包后的 `Info.plist` 核对）。
* `tauri.conf.json` 的 `bundle.fileAssociations` 要留着：它供 Windows 安装器与 Linux 桌面注册用，mac 这一侧由 plist 接管。两处都得写，删任一处就少一个平台。

要点：

- `data-tauri-drag-region` 和 `-webkit-app-region: drag` 双写，前者是 wry 的拖拽区标记，后者是 WebKit 的，两个都认，稳妥。
- 按钮区 `.win-btns` 和每个 `button` 都 `no-drag`，否则按钮点不动、还触发拖窗。

- `backdrop-filter` 只在 Windows 分支用；Linux 分支不写，避免依赖毛玻璃。

### 2.3 `src/titlebar.js`（新建）

```js
// titlebar.js —— Windows / Linux 自定义标题栏按钮 + 平台标记 + 双击最大化
import { getCurrentWindow } from '@tauri-apps/api/window'

const inTauri = '__TAURI_INTERNALS__' in window

/** 给 <html> 打 data-tauri-platform，供 CSS 分平台出样式。没装 plugin-os，用 UA 判，浏览器裸跑也能用。 */
function markPlatform() {
  const ua = navigator.userAgent
  let p = 'linux'
  if (/Macintosh|Mac OS X/i.test(ua)) p = 'macos'
  else if (/Windows/i.test(ua)) p = 'windows'
  document.documentElement.dataset.tauriPlatform = p
  return p
}

export function initTitlebar() {
  const platform = markPlatform()
  const bar = document.querySelector('.titlebar')
  if (!bar) return

  // 非 Tauri（vite 裸跑 :1420）不接窗口控制，按钮留着但不报错
  const appWindow = inTauri ? getCurrentWindow() : null
  const btnMax = bar.querySelector('[data-win="max"]')

  if (!appWindow) return

  bar.querySelector('[data-win="min"]')?.addEventListener('click', () => appWindow.minimize())
  bar.querySelector('[data-win="close"]')?.addEventListener('click', () => appWindow.close())
  btnMax?.addEventListener('click', async () => {
    await appWindow.toggleMaximize()
    refreshMaxIcon()
  })

  // 最大化态换图标：还原（双框）<-> 最大化（单框）
  async function refreshMaxIcon() {
    const use = btnMax?.querySelector('use')
    if (!use) return
    const max = await appWindow.isMaximized()
    use.setAttribute('href', max ? '#i-win-restore' : '#i-win-max')
    btnMax.title = max ? '向下还原' : '最大化'
  }
  refreshMaxIcon()
  appWindow.onResized(refreshMaxIcon)

  // 双击标题条最大化/还原。macOS 的 Overlay 原生已支持，别再挂一份免得双触发。
  if (platform !== 'macos') {
    bar.addEventListener('dblclick', (e) => {
      if (e.target.closest('button')) return
      appWindow.toggleMaximize()
    })
  }
}
```

`refreshMaxIcon` 需要在 `btnMax` 监听器作用域里能访问，上面把它定义成函数声明（提升），`btnMax?.addEventListener` 里可直接调。

## 3. macOS 主窗口自定义标题条

macOS 不写自定义按钮，靠系统红黄绿 + `titleBarStyle: "Overlay"`。前端这侧只做三件事，都在第 2 节里已覆盖：

- 顶部 `.titlebar` 条 `padding-left: 78px`，给红黄绿按钮留位，内容不压上去。
- 拖拽区（`.titlebar` 本体）从按钮右侧起算，避开红黄绿——靠 padding 把起始位置推到按钮右边即可。
- 双击最大化由系统 Overlay 原生处理，前端不挂（`titlebar.js` 里 `platform !== 'macos'` 分支已跳过）。

屏幕顶部的 App 主菜单（文件 / 编辑）继续用现有 `set_mac_menu`，Overlay 不影响它，两者共存。

## 4. 唤醒隐藏主窗口的固定动作

无论菜单栏还是托盘，把主窗口从隐藏/失焦状态唤回前台，Rust 侧固定两连：先 `show()` 再 `set_focus()`。只 `show()` 不 `set_focus()` 窗口可能起来但不抢焦点；只 `set_focus()` 不 `show()` 对已 hide 的窗口无效。

```rust
if let Some(win) = app.get_webview_window("main") {
    let _ = win.show();
    let _ = win.set_focus();
}
```

## 5. macOS 菜单栏状态图标

两个方案。**方案 A 是 Tauri v2 托盘**，在 macOS 上底层就是 `NSStatusItem` + `NSMenu`（tao 用原生对象搭的），Rust 侧三十来行、跨三端通用、不碰 Swift 构建，推荐。**方案 B 是纯 Swift 插件**，字面意义手写 `NSStatusItem` + `NSMenu`，macOS 独有，需要 Swift 构建接入，重但灵活。

两个方案二选一，别同时上（会出两个图标）。

### 方案 A：Tauri v2 托盘（推荐）

`src-tauri/Cargo.toml` 给 tauri 加 `tray-icon` feature：

```toml
tauri = { version = "2", features = ["protocol-asset", "tray-icon"] }
```

`lib.rs` 建托盘 + 菜单，事件转发给前端。菜单项：显示主窗口 / 新建笔记 / 打开最近（子菜单）/ 退出。点前两项先唤窗口再 `emit` 给 JS 干活（新建笔记、打开最近都要动 ProseMirror 和索引，逻辑在 webview 里，Rust 只负责唤窗 + 转发）。退出也走 JS，让它跑未保存询问（复用现有 `core:window:allow-destroy` 那条链路）。

```rust
use tauri::tray::{TrayIconBuilder, TrayIconEvent, MouseButton, MouseButtonState};
use tauri::menu::{MenuBuilder, SubmenuBuilder, MenuItemBuilder, PredefinedMenuItem};
use tauri::{Emitter, Manager};

fn build_tray(app: &tauri::AppHandle) -> Result<(), String> {
    let show = MenuItemBuilder::with_id("show", "显示主窗口").build(app).map_err(|e| e.to_string())?;
    let new_note = MenuItemBuilder::with_id("new", "新建笔记").build(app).map_err(|e| e.to_string())?;
    let recent = SubmenuBuilder::new(app, "打开最近").build().map_err(|e| e.to_string())?;
    let quit = MenuItemBuilder::with_id("quit", "退出 NoteLume").build(app).map_err(|e| e.to_string())?;
    let sep = PredefinedMenuItem::separator(app).map_err(|e| e.to_string())?;

    let menu = MenuBuilder::new(app)
        .items(&[&show, &new_note, &recent, &sep, &quit])
        .build()
        .map_err(|e| e.to_string())?;

    let icon = app.default_window_icon().cloned().ok_or("缺窗口图标")?;
    let tray = TrayIconBuilder::new()
        .icon(icon)
        .tooltip("NoteLume")
        .menu(&menu)
        // 左键不弹菜单，统一交给 on_tray_icon_event 唤窗口；菜单走右键
        .show_menu_on_left_click(false)
        .on_menu_event(|app, event| {
            match event.id().as_ref() {
                "show" | "new" => {
                    if let Some(w) = app.get_webview_window("main") {
                        let _ = w.show();
                        let _ = w.set_focus();
                    }
                    let _ = app.emit("notelume://menu-action", event.id().as_ref());
                }
                "quit" => {
                    // 走窗口关闭，触发前端未保存询问（core:window:allow-destroy 链路）
                    if let Some(w) = app.get_webview_window("main") {
                        let _ = w.close();
                    }
                }
                _ => {}
            }
        })
        .on_tray_icon_event(|tray, event| {
            if let TrayIconEvent::Click {
                button: MouseButton::Left,
                button_state: MouseButtonState::Up,
                ..
            } = event
            {
                let app = tray.app_handle();
                if let Some(w) = app.get_webview_window("main") {
                    let _ = w.show();
                    let _ = w.set_focus();
                }
            }
        })
        .build(app)
        .map_err(|e| e.to_string())?;

    // macOS：把托盘图标标成 template，自动跟随菜单栏明暗配色
    #[cfg(target_os = "macos")]
    let _ = tray.set_icon_as_template(true);

    Ok(())
}
```

在 `run()` 的 `.setup()` 里调它：

```rust
.setup(|app| {
    #[cfg(not(target_os = "macos"))]
    {
        if let Some(win) = app.get_webview_window("main") {
            win.set_decorations(false).map_err(|e| e.to_string())?;
        }
    }
    build_tray(app.handle())?;
    Ok(())
})
```

图标说明：现在用 `default_window_icon()`（即 `tauri.conf.json` 的 `bundle.icon`）兜底，能编译过。要更贴 macOS，做一张黑底透明的单色 `src-tauri/icons/tray.png`（32x32 或 44），把上面 `let icon = ...` 换成 `tauri::include_image!("icons/tray.png")`，再 `set_icon_as_template(true)`，菜单栏里会自动反白。

行为说明：`show_menu_on_left_click(false)` 后，左键点图标 = 唤窗口，右键点 = 弹菜单，三端一致。macOS 上右键（或 Ctrl+点）弹菜单是常态，符合预期；想左键就弹菜单把它设 true，但那样左键就不能唤窗口了，二选一。

### 方案 B：Swift 插件手写 NSStatusItem + NSMenu（macOS）

只有明确要 Swift/AppKit 掌控（比如要自定义图标视图、要 NSPopover、要区分左右键的特殊行为）才走这条。它是 macOS 独有，且要把 Swift 编进 Rust 产物，构建链比方案 A 重。

先用官方脚手架生成插件骨架（会带 `Package.swift`、`build.rs`、FFI 胶水）：

```powershell
npm run tauri plugin new status-bar
```

然后在插件的 Swift 包里实现状态项。核心 `StatusBarPlugin.swift`：

```swift
import AppKit
import Tauri

final class StatusBar: NSObject, NSMenuDelegate {
    private var statusItem: NSStatusItem!
    private var recentSubmenu = NSMenu()
    private weak var plugin: Plugin?

    init(plugin: Plugin) {
        self.plugin = plugin
        super.init()
    }

    func install() {
        DispatchQueue.main.async { [self] in
            statusItem = NSStatusBar.system.statusItem(withLength: NSStatusItem.variableLength)
            if let button = statusItem.button {
                button.image = NSImage(named: "TrayIcon") // 走 Assets.xcassets 的 template 图
                button.image?.isTemplate = true
                button.action = #selector(onClick)
                button.target = self
            }
            rebuildMenu()
        }
    }

    func setRecent(_ paths: [String]) {
        DispatchQueue.main.async { [self] in
            recentSubmenu.removeAllItems()
            if paths.isEmpty {
                recentSubmenu.addItem(withTitle: "（暂无最近文件）", action: nil, keyEquivalent: "")
            } else {
                for (i, p) in paths.enumerated() {
                    let item = NSMenuItem(title: URL(fileURLWithPath: p).lastPathComponent,
                                          action: #selector(onRecent(_:)),
                                          keyEquivalent: "")
                    item.tag = i
                    item.representedObject = p
                    recentSubmenu.addItem(item)
                }
            }
            rebuildMenu()
        }
    }

    private func rebuildMenu() {
        let menu = NSMenu()
        menu.delegate = self
        menu.addItem(withTitle: "显示主窗口", action: #selector(onAction(_:)), keyEquivalent: "")
        menu.addItem(withTitle: "新建笔记", action: #selector(onAction(_:)), keyEquivalent: "")
        let recent = NSMenuItem(title: "打开最近", action: nil, keyEquivalent: "")
        recent.submenu = recentSubmenu
        menu.addItem(recent)
        menu.addItem(.separator())
        menu.addItem(withTitle: "退出 NoteLume", action: #selector(onAction(_:)), keyEquivalent: "")
        for item in menu.items where item.action == #selector(onAction(_:)) {
            item.target = self
            item.representedObject = item.title
        }
        statusItem.menu = menu
    }

    @objc private func onClick() {
        // 左键点图标：唤主窗口。发事件让 Rust 侧 show()+set_focus()
        plugin?.trigger("action", ["id": "show"])
    }

    @objc private func onAction(_ sender: NSMenuItem) {
        guard let title = sender.representedObject as? String else { return }
        let id: String
        switch title {
        case "显示主窗口": id = "show"
        case "新建笔记": id = "new"
        case "退出 NoteLume": id = "quit"
        default: id = "show"
        }
        plugin?.trigger("action", ["id": id])
    }

    @objc private func onRecent(_ sender: NSMenuItem) {
        guard let path = sender.representedObject as? String else { return }
        plugin?.trigger("recent", ["path": path])
    }
}
```

Swift → Rust 的通道就是 `plugin?.trigger(...)`：它会以 `plugin:status-bar://<name>` 的名字把事件抛到 Tauri 事件总线上。上面 `trigger("action", ["id":"new"])` 变成事件 `plugin:status-bar://action`，payload 是 `{"id":"new"}`。

Rust 侧在 `run()` 里监听，统一做唤窗 + 归一化转发给 JS：

```rust
.setup(|app| {
    #[cfg(not(target_os = "macos"))]
    {
        if let Some(win) = app.get_webview_window("main") {
            win.set_decorations(false).map_err(|e| e.to_string())?;
        }
    }
    #[cfg(target_os = "macos")]
    {
        use tauri::{Emitter, Manager};
        let handle = app.handle().clone();
        app.listen("plugin:status-bar://action", move |event| {
            let id: String = serde_json::from_str::<serde_json::Value>(event.payload())
                .ok()
                .and_then(|v| v.get("id").and_then(|x| x.as_str()).map(String::from))
                .unwrap_or_else(|| "show".into());
            if id != "quit" {
                if let Some(w) = handle.get_webview_window("main") {
                    let _ = w.show();
                    let _ = w.set_focus();
                }
            }
            let _ = handle.emit("notelume://menu-action", id);
        });
        app.listen("plugin:status-bar://recent", move |event| {
            let path: Option<String> = serde_json::from_str::<serde_json::Value>(event.payload())
                .ok()
                .and_then(|v| v.get("path").and_then(|x| x.as_str()).map(String::from));
            if let (Some(w), Some(p)) = (handle.get_webview_window("main"), path) {
                let _ = w.show();
                let _ = w.set_focus();
                let _ = handle.emit("notelume://menu-open", p);
            }
        });
    }
    Ok(())
})
```

Swift 侧 `install()` 要在插件 `init`/`load` 时调用一次；`setRecent` 由 Rust 命令转下来（JS 把最近列表 `invoke` 给 Rust，Rust 再调插件）。这套 FFI / 命令注册由脚手架生成，按 `plugin new` 的产物补齐即可。

### 两个方案共同的前端接线

不管 A 还是 B，最终都 `emit("notelume://menu-action", id)` 给 JS。`main.js` 里监听并分派到既有逻辑：

```js
import { listen } from '@tauri-apps/api/event'
import { getCurrentWindow } from '@tauri-apps/api/window'

listen('notelume://menu-action', (e) => {
  const appWindow = getCurrentWindow()
  switch (e.payload) {
    case 'new':
      // 调现有新建笔记入口（Ctrl+N 那条）
      document.getElementById('btn-new-file')?.click()
      break
    case 'show':
      break // Rust 已 show+focus，这里不用动
    case 'quit':
      appWindow.close() // 走关闭链路，触发未保存询问
      break
  }
})

// 方案 B 的最近文件
listen('notelume://menu-open', (e) => {
  // e.payload 是文件绝对路径，接到打开逻辑
})
```

新建笔记直接 `click()` 现有按钮，复用 `btn-new-file` 的 handler，不重写。显示主窗口 / 退出 Rust 已处理或直接 `close()`，JS 只补 `new`。

## 6. 打包注意

- `tauri` 的 `tray-icon` feature 加了才能用 `TrayIconBuilder`（方案 A）。漏加会编译不过。
- 方案 A 的托盘图标默认取 `bundle.icon`；换 template 图标要新增 `src-tauri/icons/tray.png` 并改 `include_image!`。
- 方案 B 需要 Swift 工具链（Xcode Command Line Tools）和 `tauri plugin new` 的构建接入，仅 macOS 目标；Windows / Linux 构建会自动跳过 macOS 分支（`#[cfg(target_os = "macos")]`）。
- `capabilities` 改完要重新 `npm run tauri dev`，权限是启动时读的，改完不重启不生效。

## 7. 注意事项

**macOS 红黄绿按钮重叠**：Overlay 下红黄绿浮在内容左上，`.titlebar` 必须 `padding-left: 78px` 且拖拽区从按钮右侧起，否则自定义按钮/标题会压到系统按钮上，点击还互相抢。这就是第 2.2 节那段 padding 的由来。

**LSUIElement**：设 `true` 应用变 accessory——不出现在 Dock、不进 Cmd-Tab，且唤窗时应用可能不激活，光 `set_focus()` 不够，还得 `NSApp.activate(ignoringOtherApps: true)`。NoteLume 有完整编辑器主窗口，要常驻 Dock、要 Cmd-Tab 切换，所以**不设** `LSUIElement`（当前 `Info.macOS.plist` 保持原样）。只有做成纯菜单栏小工具、不要 Dock 时才设。

**Linux Wayland**：
- 自定义标题栏拖拽靠合成器的 move 协议，部分 Wayland 合成器对客户端拖窗支持不全，可能拖不动或只能拖边缘；X11 回退下正常。
- 托盘在 Wayland 走 StatusNotifierItem，需要一个 SNI host（如 GNOME 的 AppIndicator 扩展）；没 host 托盘不显示。测的时候在 X11 会话下验证，别只在裸 Wayland 下看。
- `set_focus` / 激活在部分合成器下是 no-op，弹窗抢焦点行为不一致。
- 标题栏阴影、圆角各家合成器不同，别假定有 DWM 那套。

**Windows 阴影丢失**：`set_decorations(false)` 会连系统投影一起干掉，Win11 下窗口还会丢圆角。缓解：给窗口根节点留 1px 透明边模拟，或用 `windows` crate 调 `DwmExtendFrameIntoClientArea` / Win11 的 `DWMWA_WINDOW_CORNER_PREFERENCE` 补圆角。完全复原 DWM 那套阴影较难，多数自定义标题栏应用选择接受方角 + 自己画分隔线。当前 `style.css` 用 `border-bottom` 给标题栏收边，视觉上能接受。

**Tauri 托盘 vs 原生 NSStatusItem**：macOS 上 Tauri 托盘底层就是 `NSStatusItem` + `NSMenu`，只是用 Rust 搭，跨三端一套代码。原生 `NSStatusItem`（方案 B）能完全掌控 AppKit——自定义 button 视图、NSPopover、左右键细分行为——但 macOS 独有、要 Swift 构建接入。要跨端统一用方案 A，要 macOS 极致原生操作用方案 B。

**ProseMirror 别塞 NSPopover**：popover 小、瞬态、自动尺寸，ProseMirror 要稳定宽高、滚动、输入法（IME）组合区，塞进去会互相打架（popover 抢焦点、尺寸跳动、滚动位置丢）。编辑留在主窗口，popover 至多做个「快速记录」的轻量输入，别把完整编辑器搬进去。这也是 macOS 主窗口坚持用 Tauri 渲染 ProseMirror、不做纯 popover 面板的原因。
