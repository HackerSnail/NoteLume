# 超大文件虚拟化编辑器（① 分片/分页渲染 + ② Rust 后台解析 + ④ 懒加载）

## 目标与硬约束

- 目标：MB 级（乃至 10MB+）markdown 在 WYSIWYG 下秒开、滚动/编辑不假死，且光标/选区/undo/库内查找/折叠/大纲跨整篇可用。
- 硬约束（决定这是重写而非补丁）：
  - ProseMirror 的 `EditorView` 为整篇文档维护 DOM，不支持 DOM 虚拟化；`posAtDOM`/`coordsAtPos`/`domAtPos`/`nodeDOM`（`editor-view.js:388/495/567`、`table-editing.js:125`、`wysiwyg-gutter.js:129`、`slash-menu.js:129`、`suggest-plugin.js:90`）只在有 DOM 的区间有效。
  - 现有约 20 个插件与功能建立在「整篇模型 + 整篇 DOM」上（`editor-view.js:12-43` 的 import 清单）。
  - 初次解析不是冻结主因，主因是主线程铺 DOM + 每块强制布局；故 ② 必须与 ①/④ 同时成立才有效。
  - 与 CLAUDE.MD「单文档一体化 WYSIWYG、对标 Typora」定位、以及「编辑器实例池 已否决」的判断冲突，需要产品层面确认。

## 总体架构

单一事实源 = 内存里的完整 PM 文档（master doc）。在其上加一层「窗口化视图」：

- Master 层：完整 doc、history、索引、大纲、库内查找、折叠状态、序列化（保存）都在 master 上算，与 DOM 无关。
- Window 层：`EditorView` 绑定一个「窗口 state」，其 doc 是 master 顶层块的一个连续切片 `[i0..i1]`（含首尾哨兵块与上下 spacer 撑出真实滚动高度）。用户只在窗口内编辑。
- 同步：窗口内的事务提交后，按块偏移把变更回灌 master 对应区间；master 变化（如外部改动、查找跳转）驱动窗口重切。窗口随滚动扩缩（overscan 若干块），跨越边界时重映射选区。
- 坐标类功能：只在窗口内解释（用户编辑处必可见，可接受）；跨窗口跳转（点大纲/查找命中在窗口外）先移动窗口到目标块，再落选区。
- 装饰类插件（hl/emoji/toc/csv/mermaid/footnote/find 高亮）：改为「按窗口区间计算」而非全篇 `doc.descendants`，off-window 命中不渲染但在 master 保留。

Rust 后台解析（②）：
- 新命令 `md_to_pm_json(md, opts) -> PM 节点 JSON`（`src-tauri/src/` 新增模块），用 Rust markdown 解析器（如 pulldown-cmark）复刻 `editor-schema.js` 的 GFM + 自定义行内规则（`[[wikilink]]`、`#tag`、`$math$`、脚注、任务项、图片尺寸、callout），产出与 schema 对齐的 JSON；JS 侧 `Node.fromJSON(schema, json)` 重建 master doc。
- 边界：Rust 只做「初次大文件解析」；增量输入、序列化（PM->md）、小文档仍走现有 JS 解析器为唯一权威，避免双实现漂移。大文件首屏后如需与 JS 解析对拍，用固定用例集回归。

## 分阶段（每阶段末有 go/no-go 或验收）

### Phase 0：可行性 spike（先做，设硬闸）
- 目标：用最小原型证明「窗口化 EditorView + master 回灌」能保住光标/选区/undo/滚动条高度不崩。
- 做法：新建实验分支，实现 master/window 切片 + 上下 spacer + 单向前滚窗口；只接最小编辑与 undo。
- 判定：若选区/undo/IME/块在窗口边界拆分合并无法稳定，则「全可编辑虚拟化」在 PM 上不可行 -> 停，转「降级保真」（只读窗口浏览，见回退）。
- 交付：spike 报告 + go/no-go 决策。

### Phase 1：Rust 初次解析（独立、可并行、风险较低）
- 新增 Rust 解析模块 + `md_to_pm_json` 命令；`capabilities` 注册；`tauri-bridge.js` 加 invoke 封装。
- 用例对拍：把 `editor-schema.js` 现有解析测试的输入喂给 Rust，断言 PM-JSON 结构一致（wikilink/tag/task/math/footnote/图片尺寸/表格/callout）。
- 主线程：大文件打开时 `invoke` 取 JSON，异步建 master doc，不阻塞 UI。
- 验收：10MB 解析在后台完成、主线程无长任务；与 JS 解析产物逐块一致。

### Phase 2：窗口化渲染内核
- 实现 master/window 双向同步、块索引与偏移表、滚动 spacer 与 overscan、跨边界选区重映射。
- 保存仍序列化 master（无损）；脏标记/自动保存跟 master。
- 验收：10MB 打开后仅窗口块入 DOM，滚动流畅、编辑即时、光标/选区正确。

### Phase 3：功能重接到 master/窗口双轨
逐个改造依赖整篇的模块（见回归面表），使其读 master 算结果、只在窗口渲染。
- 库内查找 `find-in-doc.js`：命中/替换在 master 算，装饰只铺窗口内命中；跳转先移窗口。
- 大纲/标签 `emitMeta`/`outline-tree.js`、反链、索引：走 master（本就模型级，改动小）。
- 折叠 `fold-plugin.js`、行号 `wysiwyg-gutter.js`、`hl/emoji/toc/csv/mermaid/footnote` 装饰：按窗口区间计算。
- WYSIWYG<=>源码 `pos-map.js`/`source-sync.js`：源码态用整篇原文（CM 已虚拟化），回 WYSIWYG 时窗口定位到光标块。
- 验收：跨窗口点大纲/查找命中能正确跳转并编辑；undo 覆盖跨页操作。

### Phase 4：阈值与降级策略、性能与内存收尾
- 与已上线的 `LARGE_MD_LIMIT`（`main.js`）整合：小文档走原单视图路径（零改动、零风险），仅超阈值启用虚拟化 + Rust 解析；阈值/开关进设置页。
- 内存：master doc + 窗口 DOM 的峰值实测；必要时限制窗口大小与缓存。
- 全量回归 + 真机（Ubuntu 24.04/X11 与 Windows）用 10MB 样例验证。

## 回归面与逐模块处置

| 模块 | 现状依赖 | 虚拟化后处置 |
| --- | --- | --- |
| `find-in-doc.js` | `doc.descendants` 全篇命中 + 全篇装饰 | 命中/替换留 master；装饰按窗口；跳转先移窗 |
| `wysiwyg-gutter.js` | `doc.forEach`+`nodeDOM` 全篇 | 已窗口化；改为窗口内块 |
| `hl-decorations.js`/`emoji-decorations.js`/`toc-block.js`/`csv-preview.js`/`mermaid-preview.js`/`footnotes.js` | `doc.descendants` 全篇装饰 | 按窗口区间产装饰 |
| `fold-plugin.js` | 全篇折叠态 | 折叠态存 master，窗口内渲染 |
| `table-editing.js`/`table-picker.js`/`slash-menu.js`/`suggest-plugin.js` | `coordsAtPos`/`domAtPos` | 窗口内有效，无需改（编辑处必可见） |
| `pos-map.js`/`source-sync.js` | 整篇序列化映射 | 源码态用整篇原文；回 WYSIWYG 定位窗口 |
| `outline-tree.js`/反链/索引 | 模型级 | 读 master，改动小 |
| `history`（undo/redo） | 绑定单 state | 需桥接 window 事务到 master history |
| 保存/自动保存/脏 | 序列化整篇 | 序列化 master（不变） |

## 关键风险

- 窗口边界：块在边界被拆分/合并/增删导致索引与选区错乱（最难，Phase 0 主攻）。
- undo/redo 跨窗口一致性；IME 组合输入在窗口重建时丢字。
- 双解析器（Rust 初次 / JS 增量）产物漂移 -> 文件往返损坏；靠对拍用例与「JS 为编辑权威」约束兜。
- 内存：10MB 的 master doc 树 + 索引常驻。
- 与产品定位冲突：Typora 式单文档体验被「窗口/分页」语义扰动。

## 回退方案（Phase 0 失败或成本不可接受时）

- 降级保真：超阈值默认只读 + 窗口化浏览 + 按节（标题）载入可编辑子文档；跨页查找/折叠/连续 undo 明确禁用。即此前评估的「混合」档。
- 或维持现状（>2MB 自动源码模式，已上线），仅把阈值与只读/关装饰做成开关。

## 成本与验收

- 量级：Phase 0 约 3-5 人日验证；通过后 Phase 1-4 合计以「周」计（内核重写 + 约 12 个模块重接 + 双端真机回归），属高风险大改。
- 总验收：10MB 样例打开 < 1s 出首屏、滚动/编辑无假死；光标/选区/undo/库内查找/折叠/大纲跨整篇可用；保存与原 JS 路径逐字节一致；五语言与既有测试不回归。

## 建议

先只做 Phase 0 spike 并据此 go/no-go，不要一次性承诺全量实现；② 的 Rust 解析（Phase 1）可与 spike 并行，因它独立且风险较低。若 spike 证明 PM 无法稳定承载全可编辑虚拟化，则落到「回退方案」的降级保真档。
